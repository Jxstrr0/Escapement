# Escapement: build plan

A watchmaking career game by Longlight Interactive. Build mechanical movements part by part, put them on the timegrapher, chase chronometer certification, and sell to customers, collectors and auction houses until you run a full manufacture making your own calibres. Phone-first, free, hosted on GitHub Pages, listed on Kelbo.Website.

Hand this file to a Claude Code session, e.g.:

> Read `CLAUDE.md` (if it exists yet), then `docs/ESCAPEMENT-PLAN.md`. Do PR 0 only. Stop when it's merged and give me the phone test.

Commit this file as `docs/ESCAPEMENT-PLAN.md` in the `Escapement` repo so every session can find it. Tick off PRs in the checklist at the bottom as they land. Decisions already made are in section 1. Open questions are listed per PR in section 12; ask them before the PR they affect.

## 0. Ground rules

- **Stack is PEW's stack, lifted directly.** Reference repo: `github.com/Jxstrr0/350Chev` (read its `CLAUDE.md` and `src/README.md` first; copy `build.js` and the shape of `check-savecode.js`). Plain HTML, CSS and classic (non-module) JavaScript in `<script>` blocks. No package.json, no npm, no bundler, no CI. three.js r128 from CDN (same `PEW_LIBS` on-demand loading pattern). Google Fonts only.
- **Edit `src/` only.** `index.html` and `sw.js` are generated by `node build.js` from `src/manifest.txt`. Run `node build.js`, `node build.js --check`, `node check-savecode.js` before every commit. Commit `src/`, `index.html`, `sw.js` together.
- One `claude/...` branch + PR per section below. Keep each PR readable on a phone. Bump the **third** VERSION number (`src/app/state.js`) per PR; the fourth for hotfixes. Merge commit title `x.y.z.w: summary`.
- **Three graphics tiers** (`lite`, `full`, `ultra`, `src/app/perf.js`). Lite is the phone default and must keep working after every change. Every effect needs a Lite path that is cheaper, not just "off".
- **Three namespaces, same split as PEW:** `WATCH_SIM` (physics and economy maths; never touches DOM or three.js; runs in plain node), `WATCH_VIS` (three.js; reads the movement config), and the app glue in `src/app/`.
- **Tuning numbers live in tables, not inline.** Every table is named in this plan; use those names.
- All localStorage access wrapped in try/catch. Keys: `esc-save`, `esc-slot1` to `esc-slot3`. A new key must be added to `buMake`/`buWrite` in `savecode.js`; stop and ask before adding one.
- Save codes: `ESC1:` + the keys as JSON, LZW-squeezed, base64url, + 6-char checksum. Restore checks the whole code before writing anything.
- Respect `prefers-reduced-motion` and `prefers-reduced-transparency`. Light theme (`:root[data-theme=light]`) gets every change.
- Comments in plain English at the top of each file say what it holds.
- Real design decisions get asked, not guessed.
- End each PR with a plain-language "what changed / how to test on a phone" summary.
- Deploy: GitHub Pages serves the repo root from `main` (`.nojekyll`). Merging into `main` is the deploy.

## 2. Direction

PEW's loop with the race swapped for the market: **Bench → Build → Timegrapher → Adjust → Certify → Sell → Reputation → bigger shop → harder movements.**

What must feel great, in order:

1. The **timegrapher trace** (the dyno chart equivalent). Two scrolling dot lines; their gap is beat error, their slope is rate.
2. The **tick**. A synthesized tick from the beat rate. 18,000 bph sounds lazy, 36,000 hums, beat error makes it uneven. This is the engine voice.
3. The **stress report** and certification verdict. Plain English about what will go wrong and why.
4. The 3D movement actually ticking at the ratio you built.

Look: quiet, warm bench light, brass and steel on dark felt. Brand font stays Longlight (Space Grotesk for UI; a tabular mono for readouts). Not PEW's orange; pick a brass/felt palette (ask in Q2).

## 4. PR 1: Movement sim (text only)

All in `src/sim/`. No DOM. Runs in node (same cut-the-bundle trick as PEW; the sim block ends with `module.exports = WATCH_SIM`).

### 4a. Parts tables (`src/sim/parts.js`)

`PARTS` is an object of slots; each slot is an array of options with `id`, `name`, `cost`, `hours`, `prestige`, `unlock` (`start` | `shop` | `rnd:<id>`), and the stats below. `DEFAULT_CFG` is a plain manual 28,800 bph three-hand movement. Starting numbers are a first guess; tune in node.

| Slot | Options (first pass) | Stats that matter |
|---|---|---|
| `barrel` | single-small, single-large, double, high-torque | `torque` (N·mm equiv, use 0..10 scale), `falloff` (0..1 torque lost across reserve), `reserveH` |
| `train` | standard, polished-pivots, fine-pitch | `friction` (0..1), max `bph` supported |
| `jewels` | 17, 21, 25, 31 | `friction` multiplier, `prestige` |
| `escapement` | swiss-lever, hi-eff-lever, coaxial-style (R&D), detent (R&D) | `efficiency` (0..1), `oilDrift` (rate change per service-year), `shockFragile` (0..1), `lubeFree` |
| `balance` | smooth-small, smooth-large, screw, free-sprung (R&D) | `inertia`, `poise` (0..1 base quality), `freeSprung` |
| `hairspring` | steel-flat, steel-overcoil, alloy-flat, alloy-overcoil, silicon (R&D) | `tempCoeff` (s/day/°C), `magnet` (0..1 susceptibility), `overcoil`, `brittle` |
| `bph` | 18000, 21600, 28800, 36000 | `rateStability`, `reserveMult`, `wearMult` |
| `regulator` | index, micro-adjust, free-sprung (needs free-sprung balance) | `drift` (s/day/year), `adjustRes` (smallest step) |
| `shock` | none, basic, premium | `shockRating` (0..1) |
| `winding` | manual, automatic | `thickness`, `keepsWind` (automatic holds torque near the top of the curve when worn) |
| `complications[]` | date, gmt, power-reserve (R&D), moonphase (R&D), chrono (R&D), annual-cal (R&D), perp-cal (R&D), tourbillon (R&D), repeater (R&D), split-seconds (R&D) | `torqueDraw`, `thickness`, `partCount`, `prestige`, `complexity` (skill needed) |
| `finish[]` | none, anglage, perlage, stripes, black-polish | `hours`, `prestige` only |

### 4b. The maths (`src/sim/movement.js`)

`simulate(cfg, skills, tools)` returns a result object. Keep every constant in a `K` table at the top.

- **Torque at time t:** `torque(t) = barrel.torque * (1 - barrel.falloff * t / reserveH)`; automatic clamps `t` to ~8 h while worn.
- **Amplitude (degrees):** `amp(t) = K.ampScale * torque(t) * escapement.efficiency / (balance.inertia * frictionTotal)`, clamped 150..330. `frictionTotal` = `train.friction * jewels.mult * (1 + complications torqueDraw)`. Target: 270 to 310 at full wind, 220 to 250 at 24 h for a decent build.
- **Power reserve:** `reserveH = barrel.reserveH * bph.reserveMult / (1 + torqueDraw)`.
- **Rate per position (s/day):** `rate(pos, t, temp) = iso(amp(t)) + poiseErr(pos) + tempErr(temp) + regOffset + oilDrift*age`.
  - `iso(amp) = K.iso * (amp - 270)` scaled down by `hairspring.overcoil` and `bph.rateStability`.
  - `poiseErr(pos)`: a per-position vector from `balance.poise` and the player's poising skill; 0 dial-up, largest crown-down.
  - `tempErr(temp) = hairspring.tempCoeff * (temp - 23)`.
  - `regOffset`: set by the player in the adjustment loop (PR 3).
- **Beat error (ms):** `K.beatBase / (assembly skill) / tools.timingRes`, floor from `regulator.adjustRes`.
- **Shock and magnetism ratings:** from `shock.shockRating`, `escapement.shockFragile`, `hairspring.magnet`.
- **Thickness, part count, cost, hours, service interval, prestige:** sums with the multipliers above.
- **Six positions:** DU, DD, PU, PD, PL, PR. **Three temps:** 8, 23, 38 °C.

### 4c. Interactions (`src/sim/combos.js`)

`COMBOS`: rules that add a stress line and sometimes a penalty. First set:

- high bph + small barrel → "Reserve under 30 h" penalty.
- large balance + low torque → "Amplitude below 220° at full wind".
- detent escapement + no/basic shock → "Drop test risk" with high return chance.
- steel hairspring + chrono + no shock → "Will not hold rate on the wrist".
- silicon hairspring + any drop-test fail → "Hairspring cracked" (brittle).
- automatic + thickness over limit → "Too thick for the case" (case limits come in PR 5).

### 4d. Node tests

`tools/sim-test.js`: runs `DEFAULT_CFG` and ~10 named test builds (`TEST_BUILDS`), prints amplitude at 0/24 h, six-position rates, beat error, reserve, verdict. Put the before/after numbers in the commit message whenever physics changes.

**Phone test:** none visual. The Test tab shows the raw result object as text for now.

## 6. PR 3: Timegrapher, adjustment, certification, tick

### 6a. Timegrapher (`src/app/test.js`)

- Canvas trace: time on x, rate deviation on y; two dot rows (tick/tock) whose vertical gap is beat error and whose slope is rate. Scrolls left at a steady pace for ~12 s per position. Readout: rate (s/d), amplitude (°), beat error (ms), lift angle shown as a setting.
- Position cycling buttons (DU, DD, PU, PD, PL, PR) and a temp toggle (cold/room/warm) if the owned timing machine supports it (`TOOLS` table: `timing-basic` one position, `timing-six` six positions, `timing-lab` adds temps).
- Lite: lower dot density, 30 fps cap.

### 6b. Adjustment loop

- After the first test: **Regulate** (shifts `regOffset`, step size from `regulator.adjustRes`, skill adds noise), **Adjust beat** (reduces beat error toward the skill floor), **Poise** (reduces positional spread, costs more hours). Each costs hours and advances the week clock.
- Skills (`SKILLS` table in `src/app/state.js`): assembly, regulating, poising, finishing, complications. Each levels with use; curves in `SKILL_XP`.

### 6c. Certification (`src/sim/trial.js`)

`runTrial(cfg, adjust, tier)` simulates 15 days across five positions and three temps with small daily noise. Tiers in `CERT`:

| Tier | Mean rate | Max variation | Position spread | Beat error | Amp at 24 h |
|---|---|---|---|---|---|
| Bench pass | ±30 s/d | – | – | ≤2.0 ms | ≥180° |
| Chronometer | -4/+6 s/d | ≤5 s/d | ≤6 s/d | ≤0.8 ms | ≥220° |
| Observatory | -1/+2 s/d | ≤2 s/d | ≤3 s/d | ≤0.3 ms | ≥240° |

Institute names are fictional (Q3). A certificate stamps the piece and multiplies its price (`CERT_MULT`).

### 6d. Tick (`src/sound/tick.js`)

Web Audio: a short filtered noise burst per beat at `bph/3600` Hz (28,800 bph = 8 ticks/s). Tick and tock get slightly different filters. Beat error delays alternate ticks by the ms value, so you hear it. Plays while the Test tab is open and the movement is wound. Mute toggle. Respect the same sound settings pattern as PEW.

**Phone test:** run a test on Lite, cycle positions, hear the tick change with bph and beat error, regulate a piece into Chronometer, fail one on purpose and read the verdict.

## 7. PR 4: 3D movement on the Bench tab

`src/vis/`, three.js r128, Lite first.

- **Parametric movement (`vis/movement.js`):** plates and bridges as simple extruded shapes; every wheel built from its part-table row (tooth count, diameter, thickness) as an extruded gear profile. Barrel, centre, third, fourth, escape wheel, pallet fork, balance with hairspring (a flat spiral line). Gear rotation ratios come from the train so it visibly ticks at the right rate; the balance swings with the current amplitude; the pallet fork flicks per beat. Complications add their modules as extra stacked shapes (date ring, chrono runner, tourbillon cage rotating once a minute).
- **Camera:** orbit, pinch zoom, double-tap "loupe" zoom to the escapement. Exploded view toggle.
- **Lite:** merged geometry, no shadows, no post; cap wheel tooth counts in the mesh (visual only) to keep triangle count low. Full: shadows and a brass/steel material set. Ultra: bloom on polished parts.
- `WATCH_VIS.setMovement(cfg)`, `.setRun({amp, bph, beatErr, wound})`, `.setView(name)`, `.fps()`. The app calls these; the vis never reads game state.

**Phone test (Lite):** change the train and watch the wheels rebuild; the escape wheel rate matches the bph; auto-adjust toast (from `perf.js`) does not appear.

## 8. PR 5: Shop, money, saves

`src/app/shop.js`, `src/sim/market.js`, tables at the top of `src/app/state.js`.

- **Career start:** Repair bench (year 2000, a shared bench, basic timing machine, small cash). **Skip ahead** button on new game: 2008, own shop, `timing-six`, cleaning machine, enough cash for stock, tutorial done.
- **Repairs (early income):** a queue of customer watches with a fault (`FAULTS` table: magnetized, dry, broken mainspring, bent hairspring, worn pivots, water). Diagnose with the timegrapher (the trace shows the fault pattern), pick the fix, hours and parts cost, paid on return. Teaches the parts.
- **Retail pieces:** build to stock, price it, sells over weeks based on demand, prestige and price.
- **Commissions:** `COMMISSION_TEMPLATES`: specs (cert tier, max thickness, must-have complications, finishing), budget, deadline in weeks, customer segment. Penalties for late or missed spec.
- **Trade supply:** batch orders of plain movements for other brands. High volume, low prestige, good cash.
- **Cases and dials (`CASES`):** a small catalogue; thickness limits create the "too thick" conflict with the build.
- **Upgrades (`UPGRADES`):** timing machines, cleaning machine, lathe, mill, CNC, climate control, display window, second bench, clean room. **Staff (`STAFF`):** watchmakers with skill profiles and salaries; they take repairs and trade work off your hands.
- **Finance:** weekly cash flow, rent, salaries, parts stock. Game over is bankruptcy with a restart offer.
- Save/Restore with `ESC1:` codes. Three slots.

**Phone test:** play the first in-game year on Lite: repairs, a retail piece, a commission, buy an upgrade, back up and restore.

## 9. PR 6: Career calendar, reputation, events

- **Calendar:** weeks from 2000 to 2030. Dated events: the yearly **valley fair** (show pieces, meet segment customers), the **chronometry trial** (your piece vs rivals over 30 simulated days, head-to-head like a PEW race, prize money and press), and **auction nights** (live bid drama for prestige pieces; bids scale with collector reputation).
- **Reputation tracks (`REP_TRACKS`):** collectors (finishing, complications), trade (reliability, price), press (accuracy, novelty). Each unlocks customers and events. `REP_TIERS` names the tiers.
- **Rivals (`RIVALS`):** a handful of named shops with styles; they place in trials and bid at auctions.
- **Service returns and drop tests:** sold pieces come back on a chance from shock, magnetism and oil drift. A return costs cash and reputation and plays the "cracked crystal" fail effect (reuse PEW's `failFlash` pattern; the crack is a cheap SVG overlay).
- **Smartwatch shift, 2015 to 2018 (`MARKET_ERA`):** trade orders −35%, retail −20%, repairs −40%, press interest in accuracy down; from 2019 the collector segment grows +40% and finishing prestige pays more. Shown as news cards on the Career tab, not a cutscene.
- **Goals (`GOALS`):** first Chronometer, first commission, own shop, first trial podium, first auction sale, own calibre, Observatory grade, a complete perpetual calendar, survive 2018 with staff kept on.

**Phone test:** advance two years, enter a trial, sell at auction, take a service return, read the 2015 news cards.

## 10. PR 7: Complications and R&D

## 13. Performance budget (all PRs)

- Lite: one three.js scene, merged geometry, no shadows, no post, ≤60k triangles for the movement.
- Timegrapher canvas: no more than 30 fps on Lite; draw only new dots, never redraw the whole trace.
- Tick audio: one oscillator/noise node pair, scheduled ahead, never per-frame.
- Custom property writes from JS throttled and only on change.
- After each PR, on a phone: the "Graphics lowered" toast must not appear where it didn't before.
